# Plan 011 — Category budget envelopes

Written against commit **`614cb49`** (`git rev-parse --short HEAD` should print

## Why this matters

The budget today is **total-only**: `BudgetSettings` has `totalBudget` +
split modes (STATIC/DYNAMIC), and category data exists for tagging and
analytics, but users cannot set "₹4000/month for Food". Category envelopes are
the single most requested budgeting-app feature and the natural extension of
the existing category system. This is the biggest plan in this round (L
effort) and touches the DB, so it lands **after** plans 008/009/010 in the
recommended order.

## Design decisions

- **Store the envelope on the category**, as two new nullable columns:
  `monthlyBudgetAmount: String?` (string, repo money convention) and
  `envelopePeriod: String?` (`"MONTHLY" | "PERIOD"` — PERIOD means "per budget
  period"). Null = no envelope. No new table: envelopes belong 1:1 to
  categories and this avoids join/FK churn for v1.
- **Enforcement is informational, not blocking.** Overspending a category
  warns (UI color/status) but never blocks saving a transaction — blocking is
  a product decision for later.
- **Scope = current period only** in v1: envelope progress = Σ spend of
  non-deleted, non-recurrent, non-adjustment transactions with that
  `categoryId` inside the current period boundary (reuse
  `BudgetStateCalculator.filterPeriodTransactions`). No per-envelope rollover.
- **UI entry points**: (a) category management in Settings gains a budget
  field per category; (b) Analytics category card shows progress; (c) optional
  warning chip in the editor's `CategoryToolbar` when the picked category is
  over 90% spent — keep (c) minimal or skip if time-boxed.

## Steps

1. **Schema.** Add to `CategoryEntity`:

   ```kotlin
   val envelopeAmount: String? = null,   // decimal string, money convention
   val envelopePeriod: String? = null,   // "MONTHLY" | "PERIOD"
   ```

   Bump `AppDatabase` version to 18 and add `AutoMigration(from = 17, to = 18)`.
   Build once to regenerate `app/schemas/.../17.json → 18.json` — the build
   fails if the export is missing (AGENTS.md Room-schema note). Commit the
   generated 18.json.

2. **Domain/DAO.** Mirror the fields in `Category` (as `BigDecimal?` +
   `CategoryEnvelopePeriod?` enum — convert at the mapper). Add DAO:
   `@Query("UPDATE category SET envelopeAmount = :amount, envelopePeriod = :period WHERE id = :id")`
   `suspend fun setEnvelope(id: Long, amount: String?, period: String?)`.
   Expose `suspend fun setCategoryEnvelope(categoryId: Long, amount: BigDecimal?, period: CategoryEnvelopePeriod?)`
   on `BudgetRepository` (impl maps BigDecimal→plain string, null clears both).

3. **CategoryEnvelopeCalculator** (pure, injectable like
   `RecurringExpenseCalculator`):

   ```kotlin
   data class CategoryEnvelopeStatus(
       val categoryId: Long,
       val limitAmount: BigDecimal,
       val spent: BigDecimal,
       val fractionUsed: BigDecimal,   // spent/limit, 4dp HALF_UP, capped at 9.9999
   )
   fun computeStatuses(
       transactions: List<Transaction>,   // period-filtered
       categories: List<Category>,
       periodDays: Int,                    // for MONTHLY normalization of PERIOD envelopes... (see below)
   ): Map<Long, CategoryEnvelopeStatus>
   ```

   Rules: skip categories with null envelope; spend = Σ `amount` where
   `!isDeleted && !isRecurrent && !isAdjustment && amount > 0` and
   `categoryId` matches. `MONTHLY` envelopes inside a shorter PERIOD budget
   are prorated: `limit × periodDays / daysInMonth(periodEndDate)` — keep this
   proration logic in the pure function and unit-test it.

4. **ViewModels.** AnalyticsViewModel: combine existing flows
   (+ `getActiveCategories()` already present) and attach statuses to the
   category analytics card state; render a thin progress bar + "X of Y" label
   and an over-limit color token (use theme error color; do not invent new
   colors). Editor warning (optional step): in the editor state controller,
   when the selected category's `fractionUsed >= 0.9`, surface a warning
   string under the toolbar — reuse the status map via the shared
   `BudgetViewModel`'s already-collected transactions (locate via
   `presentation/ui/budget/BudgetViewModel.kt`).

5. **Settings UI.** Wherever category management renders (search `hideCategory`
   / `CategoryToolbar` usages; Settings section "Categories"), add an "Edit
   budget" action per category opening a small dialog with a numpad-free
   decimal input (reuse `AutoResizeBasicTextField` from theme components) and
   a period toggle Monthly/Per-period/Clear.

6. **Strings** (`values/strings.xml` only):
   `envelope_label` ("Category budget"), `envelope_monthly` ("Monthly"),
   `envelope_per_period` ("Per period"), `envelope_clear` ("No budget"),
   `envelope_progress_format` ("%1$s of %2$s"), `envelope_over_warning`
   ("Category budget exceeded"), `envelope_near_warning` ("Close to category budget").

7. **Tests.** `CategoryEnvelopeCalculatorTest`: no-envelope categories absent
   from result; income/adjustment/recurrent excluded; MONTHLY proration for a
   14-day PERIOD budget (assert exact BigDecimal with scale 2 HALF_UP);
   over-limit fraction capping; period-boundary dates included (transactions
   dated on the period end date count). Follow the fixture style of
   `RecurringExpenseCalculatorTest` (same folder).
