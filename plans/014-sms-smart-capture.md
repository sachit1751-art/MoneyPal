**Status:** TODO

## Why

Today a captured SMS becomes a transaction whose comment is the raw sender
(`HDFC-BANK`), with no category and no provenance. The user's complaint:
"auto parsing of the transaction" should *finish the job* — extract the real
merchant from the message body, attach a category using the existing
suggester, and record how confident the capture was so the UI (plan 015) can
route low-confidence rows to a review inbox instead of silently budget-warping.

## Steps

### Step 1 — Merchant extraction (pure, domain/sms)

New file `app/src/main/java/com/sachit/moneypal/domain/sms/SmsMerchantExtractor.kt`:

```kotlin
/**
 * Extracts the most merchant-like proper noun from a bank SMS body.
 * Pure Kotlin, unit-tested. Returns null when nothing confident is found.
 *
 * Heuristics, in priority order:
 *  1. "at <MERCHANT>", "to <MERCHANT>", "on <MERCHANT>" following the amount
 *     (e.g. "debited for Rs 500 at AMAZON", "spent on card XX at Swiggy").
 *  2. Known-merchant dictionary hit (small seed list: AMAZON, SWIGGY, ZOMATO,
 *     UBER, OLA, NETFLIX, SPOTIFY, JIO, AIRTEL, BLINKIT, BIGBASKET, DMART...).
 *     Keep the list small and curated; unknown merchants come from rule 1.
 *  3. null.
 *
 * The result is title-cased ("AMAZON PAY" -> "Amazon Pay") and stripped of
 * trailing card/account fragments ("at Amazon Card XX1234" -> "Amazon").
 */
object SmsMerchantExtractor {
    fun extract(body: String): String?
}
```

Rules: never return a bank name (filter out tokens containing "bank", "hdfc",
"icici", "sbi", "axis", "kotak", "paytm-bank", card fragments `XX\d+`, and the
sender itself). Max 3 words. Pure regex — no Android imports.

### Step 3 — Confidence scoring (pure object, testable)

New file `domain/sms/SmsCaptureConfidence.kt`:

```kotlin
object SmsCaptureConfidence {
    /**
     * 0..100 score. Additive: sender shape (25) + merchant found (30) +
     * category suggested (25) + amount sanity (20).
     */
    fun score(
        senderLooksLikeBank: Boolean,
        merchantFound: Boolean,
        categorySuggested: Boolean,
        amount: BigDecimal,
    ): Int
}
```

Amount sanity = `amount > 0 && amount <= 1_000_000`. 60 is the plan-015
review-inbox threshold — define `const val REVIEW_THRESHOLD = 60` here and
reference it from 015.

### Step 4 — Wire the use case

In `ProcessIncomingSmsUseCase`, after parsing the match:

```kotlin
val merchant = SmsMerchantExtractor.extract(body)   // pass body through (see below)
val index = categorySuggester.buildIndex(transactions) // budgetRepository.getTransactions().first()
val suggested = if (!match.isCredit) categorySuggester.suggest(merchant ?: "", categories, index) else null
val confidence = SmsCaptureConfidence.score(
    senderLooksLikeBank = BankSmsParser.isLikelyBankSender(sender),
    merchantFound = merchant != null,
    categorySuggested = suggested != null,
    amount = match.amount,
)
```

- `Transaction.create(..., comment = merchant ?: match.sender, categoryId = suggested?.id, source = "sms", captureConfidence = confidence)`.
- Extend `BankSmsMatch` with the parsed `body` (constructor param) so the use
  case does not re-parse; keep the existing constructor signature for tests by
  giving `body` a default `""`.
- Inject `categorySuggester` (stateless, `@Inject constructor()` like other
  calculators).
- Credits (`isAdjustment`) get `source = "sms"` too, but no category.
